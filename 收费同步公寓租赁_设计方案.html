收费数据自动同步至公寓租赁

工业园区资产管理系统（park-admin-system）· 需求分析与设计方案 · 2026-08-12

一、需求背景

财务在【收费】模块（中心账单 bills + 收款 receipts）完成公寓房租 / 物业费 / 水电费的计费与收款；公寓管理员在【公寓租赁】模块（apartment_rentals + apartment_fees）管理房间出租与收款台账。

当前两套数据各自维护，导致：① 同一笔公寓房租可能重复录入；② 财务收款后公寓页状态不变；③ 两表之间无关联键，对不上号。

目标：收费数据变动（出账 / 收款）→ 自动反映到公寓租赁（付款状态 payment_status + 自动生成公寓收费台账 apartment_fees）。

二、现状诊断（根因）

系统里存在两套并行的"公寓收费"数据，彼此没有关联键：

体系数据链路公寓房租现状问题
A. 中心收费 contracts → units → bills → receipts 已在（合同 HT-L-0002「公寓年租」→ 单元13 → 房租账单 1800；水电已出账） 重复录入、状态不联动、无关联键
B. 公寓管理 apartment_rooms → apartment_rentals → apartment_fees 独立台账，payment_status 自管，与 A 无链接
⚠️ 已确认：公寓租金其实早就在中心收费的 bills 里了，问题不是"没有数据"，而是"两套各记各的、互不同步"。

三、关键设计卡点：粒度错配（需拍板）

中心收费的公寓合同是整栋层面的——一栋公寓楼（单元13）只有 1 个合同 HT-L-0002，对应房租/水电各 1 笔账单；而公寓租赁是房间层面的——5 个房间各 1 条 rental（301/502/703/406/208）。1 个合同 ↔ 多个房间，无法直接把"这笔收费"精确同步到"哪个房间"。

方案 A（推荐） 房间级合同

每个在住房间 = 1 个租赁合同 = 1 条账单，与 apartment_rentals 行 1:1 对应。符合园区实际（房间分别租给不同企业/员工），同步最干净。

代价：需把现有"整栋合同"拆分为房间级合同（迁移脚本，幂等）。

方案 B 整栋级合同（保留现状）

保留 HT-L-0002 整栋合同，同步时只把房租/水电汇总到楼栋维度，房间级 payment_status 仍需手工指定归属。

代价：同步粒度粗，房间状态仍半手工，治标不治本。

👉 此卡点需在动手前确认。下文方案按方案 A 展开；若选 B，第五节关联键改为"楼栋→房间手工归集"，其余逻辑不变。

四、总体方案（已与您确认）

范围：房租 + 物业 + 水电（全量） 目标：付款状态 + 自动生成公寓收费台账 架构：触发式，两套并存
  • 同步方向：中心收费 → 公寓租赁（单向，源头唯一）。
  • 触发方式：收款 / 出账时自动同步；并提供"全量同步"按钮回填历史。
  • 可逆性：公寓侧仅追加/更新由"中心收费"产生的台账（带来源标记），手工台账不受影响；可随时重跑同步。

五、关联键与数据模型变更

5.1 关联键（方案 A）

  • apartment_rentals 新增 contract_id（FK → contracts.id）。
  • 迁移：为每个在住房间创建房间级公寓合同（units 类型=公寓，code 如 C-301），并回填 rental.contract_id。
  • 同步查找：bill.contract_id → apartment_rentals.contract_id（取生效中、最近一条）。

5.2 字段变更清单

表新增字段用途
apartment_rentalscontract_id INTEGER关联中心收费合同（同步键）
apartment_feessource TEXT来源标记：中心收费 / 手工
apartment_feesbill_id INTEGER溯源到中心账单（幂等去重）
apartment_roomsunit_id INTEGER（可选）房间对应资产单元，便于扩展

六、核心同步逻辑 sync_bill_to_apartment(bill_id)

1
取 bill；若其 unit 非公寓（type != '公寓'）→ 直接返回（不影响厂房/商铺）。
2
费用类型映射：租金 → 房租，物业 → 物业费，水电 → 水电费。
3
按 contract_id 定位目标 apartment_rental（生效中、最近一条）。
4
Upsert apartment_fees：fee_type=映射值，amount=账单金额，fee_date，status 由账单状态映射（已收→已缴 / 欠费→欠费 / 待收→待缴），source='中心收费'，bill_id 用于幂等。
5
重算 该 rental 的 payment_status：依据该合同下所有账单的已收/欠费 → 已缴 / 部分 / 欠费 / 待缴。
6
写审计日志（谁、何时、同步了哪笔）。

七、触发点与新增接口

位置动作
api_receipt（收款后）更新 bills 后调用 sync_bill_to_apartment
generate_monthly_bills（出账后）生成公寓账单后调用，生成"待收"台账
/api/bills 增 / 改变更后调用同步
新增 POST /api/apartment/sync全量同步：遍历所有公寓类合同的 bills → 回填 apartment_fees + 更新 payment_status，幂等（按 bill_id 去重）

八、前端改动

  • 【公寓租赁】页：新增按钮 "同步收费数据" → 调 /api/apartment/sync，返回同步条数。
  • 【公寓收费台账】列表：增加"来源"标签（中心收费 / 手工），一眼区分。
  • 收款 / 出账后，公寓页 payment_status 自动刷新，无需手动。

九、历史数据回填与风险控制

回填

首次点击"同步收费数据"（或部署后自动跑一次）遍历所有公寓类合同的历史 bills，生成 apartment_fees 并更新状态；迁移脚本幂等，重复执行不重复插。

风险

风险应对
整栋合同改房间级，影响现有 HT-L-0002 演示数据操作前先备份 park.db；迁移脚本幂等、可回滚
双向写入导致循环/冲突单向同步（中心收费为源）；公寓手工台账带 source='手工'，不被覆盖
房间无对应客户迁移时为其建默认"公寓租户"客户，保证合同完整

十、数据流图

十一、实施进展 已落地 · 2026-08-12

1. 数据迁移（方案A：房间级合同）

  • apartment_rentals 增加 contract_id；apartment_fees 增加 source（手工/收费）、bill_id；apartment_rooms 增加 unit_id（幂等加列）。
  • 迁移函数 _migrate_apartment_contracts()：为每间在住房间建/复用房间级租赁合同 HT-AP-<单元号>，并回填 apartment_rentals.contract_id（作为同步关联键）。已生成 108 个 HT-AP 合同，全部正确挂到各房间自有资产单元。
  • 同时导入《三号楼》《八号楼》入住台账：新建楼栋 4（三号楼）、5（八号楼），资产单元（units type=公寓）117 间，公寓房间主档与出租记录 113 间，全部进入资产台账。

2. 同步核心逻辑

  • sync_bill_to_apartment(conn, bill_id)：按账单 contract_id 定位公寓出租记录 → 更新 payment_status + 生成/刷新 apartment_fees（来源=收费，幂等先删后插）。
  • sync_all_apartment_bills(conn)：全量遍历公寓类账单重建台账。

3. 触发点（已挂载）

  • 收款 api_receipt：收款后自动重算账单状态并触发同步（房间缴费状态联动）。
  • 出账 generate_monthly_bills：出账后自动全量同步。
  • 新增接口 POST /api/apartment/sync：手动全量同步（幂等，可重复执行）。

4. 前端改动

  • 【公寓管理】页标题新增 「⇩ 同步收费数据」 按钮（有权限可见），点击即全量同步并刷新。
  • 【房间收费管理】费用明细表新增 「来源」 列：收费 = 中心同步生成，手工 = 手工登记。
  • 静态资源版本号升到 app.js?v=20260812b（浏览器自动刷新）。

5. 端到端验证（真实运行系统）

实测：中心建账单（房租 1200，待收）→ 同步 → 公寓收费台账出现「来源=收费、状态=待收」； 全额收款 1200 → 账单状态「已收」、该房间出租缴费状态自动变「已缴」、台账状态「已收」。 验证后演示数据已清理，生产库保持干净。
